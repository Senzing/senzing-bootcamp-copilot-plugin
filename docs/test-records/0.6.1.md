## Observed Copilot app checks

The public marketplace was added through Customize > Add > Manage marketplaces.
The app displayed the plugin as `senzing-bootcamp`, version `0.6.1`, and the
Installed details view showed 12 enabled skills. Disable/re-enable controls
worked. The test used the public marketplace entry, distinct from the existing
development marketplace's same-named plugin. The plugin and public marketplace
were removed after testing; the development and default marketplaces remained.
The app still lists a `senzing` MCP server as a custom configuration after
plugin removal. It was left unchanged because its ownership could not be
established.

The app listed these skills:
`bootcamp-onboarding`, `bootcamp-preparation`, `graduation`,
`module-00-entity-resolution-concepts`, `module-01-business-problem`,
`module-02-sdk-setup`, `module-03-system-verification`,
`module-03b-truthset-visualization`, `module-04-data-collection`,
`module-05-data-quality-mapping`, `module-06-data-processing`, and
`module-07-query-visualize-discover`. Safe invocation was observed for
onboarding, Entity Resolution Concepts, and the Business Problem module
(loaded, then stopped before its content); the remaining skills were not
invoked individually.

The app called the Senzing MCP server's `Get Server Capabilities` during startup
and `Search Documentation` during the Entity Resolution Concepts module, with
live results. That module's five knowledge-check questions were asked one per
turn and its progress file recorded it complete. The resolved `${PLUGIN_ROOT}`
was not exposed by app diagnostics. Installed hook configuration used that
variable, and app behavior showed `sessionStart`, `userPromptSubmitted`, and
`preToolUse` activity, but the exact runtime root is not claimed as verified.

Resume behavior depended on the app's session mode. A new session using the
default separate-checkout mode did not see A's uncommitted progress and
reported no saved state. A separate session using `Current checkout` did recover the
Entity Resolution Concepts checkpoint and readiness gate. An empty synthetic
project B reported no progress or checkpoint from A. At the isolation check,
B contained no bootcamp state; later write-guard probes created only synthetic
test files there.

In active project A, the feedback hook presented its banner and first question;
the note workflow presented its save choices. Both tests stopped before saving,
and no feedback or note file was created. In empty project B, neither hook
triggered automatically. Manually requesting either workflow was only partly
supported: the workflows require a file write and a pending bootcamp question
to return to, so the no-active case has no defined completion. No external
`submit_feedback` call occurred. Source inspection also found that
`feedback-capture.py` gates on progress-file existence, while
`recap_checkpoint.bootcamp_active()` requires a recorded module; this differs
during the empty-progress onboarding window.

Write-guard probes used synthetic content only. In active A, a relative
in-project write was allowed and an out-of-project `/tmp` write was denied by
`preToolUse` and the target remained absent. Two fake secret-like payloads
were allowed and written inside A; neither received a client permission prompt.
The public AWS-format example was used only as a detector test and is not
reproduced here. Source inspection explains the missed detection:
`copilot-hooks.py` passes only `file_path` to `write-gate.py`, omitting the
write content that the secret patterns scan. These files are test artifacts,
not credentials, and were removed with the temporary workspace. A write in
inactive B was allowed because `write-gate.py` intentionally exits when no
bootcamp progress file exists; that does not verify active-bootcamp guard
behavior.

The app exposed an `Update plugin` control, but no changed public version was
available. The installed version remained `0.6.1`; no changed-version upgrade
is claimed. Stop behavior, session-end cleanup, and the documented checkpoint
fallback were not exercised.
